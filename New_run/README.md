## 收桌面模式

新增根目录入口 `run_clear_table.sh`，保持原有碗沿候选、抓法、放置姿态、下降和返程动作。每轮只处理托盘外一只碗，返回原观察位后采集新图像；这次观察同时确认上一只归位、更新托盘位置和占用，再选择下一只。托盘内的碗不会再次作为抓取目标，已使用位置不会因为一次漏检而立即变成空位。最后一只放好后仍需观察核查。

无需设备的纯软件演示：

```bash
./run_clear_table.sh --offline-demo
./run_clear_table.sh --offline-demo --scenario visual
./run_clear_table.sh --offline-demo --output-dir /tmp/clear_table_demo_new
./run_clear_table.sh --offline-demo --scenario tray_full
./run_clear_table.sh --offline-demo --scenario missing
./run_clear_table.sh --offline-demo --scenario unverified
```

`--output-dir` 应为尚不存在的新目录，防止覆盖旧结果。默认场景包含 3 只托盘外的碗、1 个已有占用、轮次之间移动托盘和变化的检测编号。它复用在线模式的任务策略及原候选执行状态机，但图像观察、规划与机械臂/夹爪反馈全部模拟；不会加载 ROS 环境或连接硬件。异常场景会有限退出并保留原因，返回非零退出码，这是预期结果。`result.json` 和每轮记录可用于检查选择、核查和原动作顺序；软件模拟不验证现场识别效果、MoveIt 可达性或实际落点。

设备连接和标定完成后使用：

```bash
./run_clear_table.sh              # 只预览，不运动
./run_clear_table.sh --execute    # 每轮一只，返回后重新观察
```

默认使用 `src/yolo_vision/config/clear_table_live.json` 和 `clear_table_vision.json`：本机 35 × 23 cm 托盘，视觉估计碗尺寸、网格搜索空位、按候选补偿放置 XY、连续两帧验证。支持 `--tray-config`、`--vision-config` 显式覆盖。`clear_table_tray.json` 仍是未标定示例。旧 `--target-zone` 和手动 XYZ 单碗命令保持原样。

搜索同时检查实测内侧矩形、YOLO 可见轮廓和已有碗的占用范围；用下一只较大碗的可放位置数量选择当前空位。这是有计算上限的启发式搜索，不保证最优装箱。每次动作完成只记录“待确认”，必须看到原位置目标消失、托盘新增相近尺寸目标、旧占用仍存在，且连续两帧稳定，才增加完成数量。识别不足、目标消失但托盘未找到、已满盘均停止或有限重看。

正常演示 `normal` 保留旧固定槽位示例；`visual` 演示三个不同尺寸的合成碗、自动选位和两帧确认。它不证明现场相机能够识别任意碗。


收桌面默认使用一份固定视觉提示的 YOLOE 模型：裁剪完整桌面 `[220,300,1000,700]` 后，在同一次推理中输出碗和托盘掩膜，不做分块。掩膜映射回原图后，再结合同帧深度、相机内参和采集时刻的 TF，得到托盘在 `base` 坐标系下的中心、方向和边界。原抓放方法继续使用，不需要贴标记，也没有颜色阈值定位分支。提示库与生成工具见 [单模型视觉流程](../docs/visual_prompt_scene.md)。

现场默认模型为 `models/visual_prompt_releases/pattern_v001/model.pt`，包含 bowl/tray 两类，输入尺寸 960、置信度 0.25；视觉配置和托盘配置的推理参数必须一致。它依赖参考物体外观，不保证识别所有碗和托盘。缺少本地模型、目标类别或分割能力时拒绝定位，不自动下载模型。以下为保留的旧双模型模式的通用示例配置，不能直接替换默认单模型配置：

```json
{
  "detector": "yolo",
  "yolo": {
    "model_path": "models/tray-seg.pt",
    "target_class": "tray",
    "confidence": 0.5,
    "imgsz": 640,
    "device": "cpu"
  }
}
```

`model_path` 可写模型绝对路径；相对路径以安装后的 `yolo_vision` package share 为基准，不以托盘配置文件所在目录为基准。支持本地 `.pt` 分割权重或包含模型及类别元数据的 OpenVINO 导出目录。实际模型中的托盘类别如果使用其他名称，应同步设置 `target_class`。模型准备方式见 [模型说明](../src/yolo_vision/models/README.md)。现场配置需要测量和验证：

| 配置项 | 含义 |
| --- | --- |
| `yolo` | 托盘分割模型路径、类别、置信度、推理尺寸和计算设备 |
| `tray_outer_size` | 托盘外轮廓的实测长、短边（米），用于检查分割后的物理尺寸 |
| `tray_size` | 与外轮廓同中心、同方向的可用内侧长、短边（米），用于限制放置区域 |
| `placement_mode`、`grid_step` | 现场使用 `grid`，网格步长默认 1 cm；搜索点数有上限 |
| `slots` | 仅旧 `slots` 模式使用固定相对点，现场网格模式为空列表 |
| `object_geometry`、`rim_outer_margin` | 现场为 `visual_rim`；碗中心与尺寸来自上沿点云，边沿余量默认 4 mm |
| `bowl_radius`、`edge_margin`、`clearance`、`position_tolerance` | 最小有效占用半径、边缘余量、物体间隙和未来放置误差余量；不代表已知碗直径 |
| `placement_confirmations`、`placement_match_tolerance` | 连续确认帧数（现场 2）和放后匹配范围（现场 5 cm），仍须完整落在托盘内 |
| `source_polygon` | `base` 坐标系下允许收拾的桌面多边形，顶点按边界顺序填写 |
| `release_z`、`release_xy_offset` | `base/tool0` 最终释放高度和工具相对期望碗落点的固定 XY 偏移；高度为 `null` 时沿用 blue 的最终释放高度 |

本版只处理一个长短边可区分的矩形托盘，外轮廓长短边比需至少为 1.12。托盘模型应分割整个托盘轮廓；少量内部遮挡可通过边界和深度一致性检查，但轮廓被挡住或超出画面时不能保证定位。外侧尺寸用于核对检测，内侧尺寸用于放置，两者不能混填；示例尺寸不是现场测量结果。

初次定位将长轴方向规范到 `base` 的正 X 半平面，后续按相差 180° 等价的方向选择与上一轮最接近的方向，以保持槽位和占用连续。相邻观察的最小等价转角大于 45° 时会拒绝；矩形本身无法辨别实际转了 180° 或换成另一只相同托盘，因此任务中不要替换托盘或大幅翻转。两轮之间可以小幅平移、转动，抓放动作期间保持静止。

模型、测量和验证完成后才将现场配置的 `calibrated` 改为 `true`。ROI、深度和 TF 需能覆盖全部待收区域及托盘；程序按同帧托盘平面投影检查整个托盘及 `source_polygon` 是否位于完整桌面 ROI 内，超出时报告 `tray_outside_detection_view` 或 `source_outside_detection_view`，不把未观察区域当作空位。托盘缺失、多个托盘、边界或深度不可靠、碗压边、对象位置不确定或归位未确认时，程序有限重观察后退出，不继续放到疑似占用处。

空位边缘与物体间隙按本轮选中碗的实际占用半径检查，`bowl_radius` 是最小尺寸基准。一次任务开始时固定原 blue 放置参数，后续只换目的地坐标，运行中编辑原配置文件不改变当前任务。最后的正常空桌面确认不占用失败重试次数，因此 `--max-reobservations 0` 也能完成正常收纳；总超时和最大观察轮数仍有效。

薄托盘不增加厚度估计，沿用原放置方式和固定高度，更新平面目标 XY，可配置一次实测的工具落点偏移。本版没有新增桌面、托盘或碗的碰撞场景；槽位间距要预留碗、张爪和退爪余量。执行一轮抓放期间托盘应保持静止，观察视野应覆盖托盘和待收区域。

## 原单碗入口

每次独立启动只处理一只碗：重新识别当前位置 → 抓取并抬升 → 到指定准备点 → 沿 Z 负方向下降并释放 → 上退 → 返回固定起始关节位置 → 退出。下一次命令重新采集图像、定位和规划。

在项目根目录使用：

```bash
./run_pipeline_place_test.sh --target-zone 左上     # 只规划完整七段路径
./run_pipeline_place_execute.sh --target-zone 左上  # 真实执行一轮并返回起点
./run_pipeline_place_test.sh --x -0.237731 --y -0.402783 --z 0.179664  # 指定当前 blue 最终释放点，只规划
./run_pipeline_place_execute.sh --x -0.237731 --y -0.402783 --z 0.179664  # 指定当前 blue 最终释放点，真实执行
```

`New_run/` 中的同名脚本转发到根目录。`--target-zone` 可选左上、左下、中间、右上、右下、blue，每条命令只接受一个目标。预览脚本拒绝 `--execute`。环境未就绪时按既有流程运行 `run_robot_prepare.sh`；已有驱动运行时不要重复启动。

真实执行还需要在示教器打开包含 **External Control** 节点的程序并按 ▶ 运行。Enable Robot 仅使能机械臂，准备脚本也不会代替示教器运行该程序。可用 `./run_grasp_position_control.sh --check` 只读检查控制条件，通过后再启动抓放命令。预览成功表示路径可规划，不能证明 External Control 已运行。

如果识别、碗沿定位成功后任务退出并报 `controller_preparation_failed`，终端现在会同时打印控制器准备失败的具体原因和日志路径；相同信息保存在 `result.json` 的 `controller_error_detail`、`controller_preparation_log` 和 `controller_exit_code` 中。

若预检通过后又报“尚无持续静止、实时的六关节反馈”，控制器准备现已在各阶段等待反馈重新满足连续静止条件（有超时），包括查询控制器后、切换前和切换后。原 0.3 秒连续静止、0.5 秒接收新鲜度及关节速度条件继续生效；持续失联、实际运动或 External Control 停止仍会失败。错误会显示静止持续时间和反馈接收间隔，预检日志即时输出以保持顺序。

也可不写 `--target-zone`，改用 `--x --y --z` 一起提供最终释放点的 `base/tool0` 坐标（米）。此模式使用 blue 的姿态和当前配置的 0.122 m 下降距离；下降完成后按原流程张开夹爪、上退并返回固定起点。两种目标模式不能混用。输入和换算后的位姿会在启动 ROS 前检查，运行时再用现场 TF 核对坐标变换。

| 目标 | 从准备点向下移动 |
| --- | --- |
| 左上 | 0.122 m |
| 左下 | 0.122 m |
| 中间 | 0.122 m |
| 右上 | 0.122 m |
| 右下 | 0.122 m |
| blue | 0.122 m |

参数位于 `src/grasp_executor/config/place_zones.json`（schema 2）：每个目标有示教参考、程序工具帧的准备位姿、自己的 `place_drop_distance` 和启用开关；`return_home` 保存共同起始关节位置及 TCP 位姿。起点来自 [当前起始点只读采集](../docs/当前起始点.md)。六点当前有效位置和姿态见 [当前放置点](../docs/当前放置点.md)，blue 的采集数据见 [blue 采集记录](../docs/records/blue_release_position.json)。

运行器将选中的参数写入本次配置快照，执行器用当前 TF 核对示教参考与准备位姿。返程目标使用保存的六个关节角，不会随每次启动位置改变。完整七段路径在抓取前全部规划并检查，返程规划失败时不会开始抓取；运动中失败沿用停止流程，不强行返程。只有释放、上退和回到起点均完成后，单次任务才成功。

当前默认视觉 ROI 为 `[220,300,1000,700]`（1280×800 原图像素），依据 2026-09-28 当前 RGB/深度观测扩大边界，覆盖蓝框所在白桌的可见范围并给桌角、碗上缘留出余量。分块尺寸同步调整为 512 像素，以保留碗的检测尺度。机械臂遮挡的区域仍需调整观察姿态才能看见。现场只放这一只碗，下一次独立命令可以从上一放置位置重新识别并抓它。相机或桌子移动后需重新检查 ROI；0 只、多只或定位失败时不运动。`--vision-config 文件` 可覆盖视觉配置，`--place-zones-config 文件` 可选择另一组示教配置。路径相对当前终端目录。

单碗入口遇到空检测会重新采集识别，与运动前几何/规划重试共用 `--max-reobservations` 额度（默认 2，即最多观察三轮，也受总超时限制）。只因空检测而重试，不会导致后续成功被标记为失败；已有的几何/规划失败记录仍保留。连续空检测用尽额度后，以 `no_targets / single_bowl_required` 退出。

日志保存在 `debug_output/place_validation/` 或 `debug_output/place_execution/`，可用 `--output-dir` 指定。`result.json` 记录目标、次数和状态，`round_0001/effective_grasp_config.json` 保存下降量与返回起点。程序没有抓牢/落座传感反馈，指令成功与物理验收分别记录。

每轮选定抓取候选后，结束时额外保存 `round_0001/grasp_pose_overlay.png`：紫色十字是最终目标 `grasp_center`，红 / 绿 / 蓝箭头是工具 X / Y / Z 轴，绿色 Y 轴为夹爪闭合方向。右上角记录物体与候选编号、基坐标系 XYZ（米）及 RPY（度）。真实执行标记 `execution_started`，仅规划标记 `planned_only`；这是应用抓取偏移后的目标 pose，不能证明机械臂已到达或已抓牢。`selected_grasp_pose.json` 同时保存精确坐标、四元数及原始采集时的投影参数。原识别图 `detection_overlay.png` 保留。没有选定候选时不生成 pose 图；缺少有效投影参数时只标数值，不猜测图中位置。

编译及隔离测试：`./run_pipeline_place_offline_test.sh`。实机测试每次单独运行一个命令，前一轮结束并检查结果后再开始下一轮。

## 夹爪未闭合仍继续抬升的修复

抓取准备点先通过 GPP 读取当前状态：已打开则用至少 3 帧、连续 0.4 秒的稳定反馈确认后通过，不重复发送 Open；未打开则发送一次 Open，确认张开并稳定后下降。到抓取点始终发送一次 Close，不要求之前控制寄存器为打开，也不再要求相对于历史位置产生变化；只检查当前闭合控制值、开口已收拢并稳定后才抬升。释放使用同样的 Open 确认逻辑。

当前设备多次张开实测位置为 676～684 原始计数，`gripper_command.py` 以 680±10 作为张开位置范围，且要求 control=0；闭合要求 control=1、位置小于 670（不能仍处于张开范围），并在 1 计数范围内稳定 `gripper_settle_time=3.0` 秒。更换夹爪或改变行程需重新校准此范围。此逻辑只确认夹爪状态，不判定碗是否抓牢。

开合指令后先等待 0.2 秒再查询；正常查询间隔 0.15 秒。GPP 单次漏回包后每 0.5 秒重新查询，沿用操作总超时预算，不重复发开合命令；不再因一次查询超过 2 秒提前失败。连续反馈间隔超过 1 秒会重新累计稳定时间。`gripper_timeout=18.0` 秒（其中预留 2 秒给进程启动/退出）内持续无反馈或未到位仍停止，不继续下降/抬升。

当前 `hand_control` 没有状态 topic/service，适配器通过 `/rosout` 中驱动的原始串口回包读取硬件寄存器，校验 CRC、ID、地址、包长度和新鲜时间戳，支持分片回包。驱动需保持 `print_raw_packets=true` 和 `/rosout` 开启（当前已有配置）；不直接使用该驱动存在字节偏移错误的 `the present position` 日志。日志缺失或包格式不匹配时会在运动前拒绝运行。没有另开串口，也没有修改外部驱动。


读取当前 `place_zones.json` 的起始关节角和位姿，按初版 4.5 倍速度上限规划返程并确认静止到位：线速度 0.0675 m/s、角速度 0.45 rad/s、关节速度上限 0.675 rad/s、MoveIt 速度比例 0.225。加速度保持原值，实际耗时取决于路径和加减速，不能保证耗时严格按速度倍率缩短。只返回，不开合夹爪，不自动上抬或重试。若刚发生释放异常，先现场确认碗已放稳、夹爪已脱离物体，再执行。Ctrl+C 请求停止。日志在 `debug_output/return_home/`。本次新增入口仅做静态检查，未实机运行。

## 圆碗径向抓取

单碗入口现使用 `circle_radial`：拟合碗沿圆心，以有符号径向决定夹爪方向，保留实际接触点和碗壁支撑检查。用户通过 RViz 截图已确认红圈左指对应 +Y；当前配置固定左指在外、右指在内。圆弧覆盖不足时启用局部碗壁备用分支；仍无可靠接触依据时拒绝并有限次重观察。详细设置、离线回放和放置精度边界见 [径向抓取修改记录](../docs/圆碗径向抓取修改_20260928.md)。
