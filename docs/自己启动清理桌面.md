设备驱动已运行时跳过本节，不重复启动。

```bash

```

## 2. 检查与预览（终端 B）

```bash
cd /home/rob/table_clean_ws
export ROS_DOMAIN_ID=2
./run_grasp_position_control.sh --check
./run_clear_table.sh
```

预览不发机械臂轨迹或夹爪开合命令。必须看到结果 `passed=true, outcome=planned`，而不是只有YOLO识别成功。`object_position_uncertain`、路径失败、托盘满等结果需要先处理原因；不要放宽条件来跳过。

## 3. 当前场景已确认后执行

当前配置 `src/yolo_vision/config/clear_table_live.json` 的 `motion_approved` 已按用户确认设为 true，可直接运行本节末尾的默认命令。下面的独立任务配置方式可用于以后需要单独管理许可的场景：

```bash
cd /home/rob/table_clean_ws
export ROS_DOMAIN_ID=2
python3 - <<'PY'
import json
from pathlib import Path
directory = Path('debug_output/manual_clear_table')
directory.mkdir(parents=True, exist_ok=True)
config = json.loads(Path('src/yolo_vision/config/clear_table_live.json').read_text())
config['motion_approved'] = True
(directory / 'approved_tray.json').write_text(json.dumps(config, indent=2) + '\n')
PY

# 使用本次配置重新预览
./run_clear_table.sh --tray-config debug_output/manual_clear_table/approved_tray.json

# 预览通过且现场已确认，再执行；此命令会重新观察和规划
./run_clear_table.sh --execute --tray-config debug_output/manual_clear_table/approved_tray.json
```

这份任务配置仅适用于已经确认的当前托盘、blue释放条件和可抓物体。更换场景、标定、模型后重新核验。已保存输出目录不可覆盖，重复命令自动生成新时间目录；需要手动指定时必须提供新的`--output-dir`。

当前正式托盘配置已启用`motion_approved=true`，可直接使用：

```bash
./run_clear_table.sh
./run_clear_table.sh --execute
```

## 4. blue释放与逐轮行为

`release_z=null`时，沿用`src/grasp_executor/config/place_zones.json`里的blue姿态和下降距离0.122 m；对应`base/tool0`释放Z为0.3016637394122519−0.122=0.1796637394122519 m。夹爪仍通过原有Open命令释放，并检查反馈。托盘空位及每个抓取候选决定放置XY，不会固定丢到原blue的同一个XY。

每次执行一只碗，释放、上退并返回保存的起点，然后重新识别。连续两帧确认放好后再继续。没有足够空间、检测缺失或放置未确认时停止。程序不做套叠收纳，也不会自动把杯子或勺子当作碗抓取。

## 5. 结果与停止

结果在命令输出的`Result: .../result.json`路径中。检查`passed`、`outcome`、`motion_completed_count`与`verified_placed_count`；已发送轨迹不等于已确认放好。

在任务终端按Ctrl+C请求取消并等待退出；异常运动使用现场示教器停止或急停，不能把关闭SSH当作已经停止。任务退出后，再在终端A结束硬件会话。
