# TF 反馈恢复（2026-09-29）

## 故障记录

任务 `6097cc5e7b54483c8d0007c2105401f9` 在 `moving_to_place` 阶段出现
`stale_robot_tf_feedback`。程序尚未确认下降到位，因此没有进入释放步骤。
停机记录为 `controller_deactivated_but_action_cancel_unconfirmed`：已停用控制器，
但没有确认轨迹动作取消完成。原日志没有记录故障瞬间的 TF 延迟，不能据此认定具体发布节点故障。

## 修改行为

- 正常情况下继续使用新鲜 TF。TF 时间戳失效或查询暂不可用时，使用新鲜 `/joint_states`
  和当前 MoveIt 的 URDF，在本地计算 `base_link -> grasp_center` 位姿。
- 启动时必须先取得新鲜 TF，并核对 MoveIt FK 与 TF 的一致性；本地 FK 与 MoveIt FK
  的差异必须小于或等于 1 微米、1 微弧度，才启用备用反馈。工具固定变换也包含在模型中。
- 备用计算只接受包含全部六个关节的测量值，继续检查接收时间、消息时间戳和有限数值；
  不使用计划轨迹、上次位置或目标位置代替测量。原 `feedback_timeout=0.5 s` 未放宽。
- 切换来源时记录 `pose_feedback_source=joint_fk`、TF 原因及时间年龄；恢复 TF 时记录 `pose_feedback_source=tf`。
- 释放依然要求轨迹执行成功、末端位置与姿态到位、机械臂静止并经过停留时间。
  关节反馈也失效、模型核对失败、轨迹失败、路径偏离或取消操作仍然中止流程。
- 没有自动重发失败轨迹、自动重抓或在未确认到位时张爪。

- `src/grasp_executor/grasp_executor/moveit_ros.py`
