# 当前桌面检测 ROI

依据本次读取的 `/camera/color/image_raw`（1280×800）及对齐深度图，单碗抓放使用蓝框所在的前方白桌。相机画面见 [原始 RGB](../debug_output/table_roi_update_20260928/rgb.png)。桌面可见部分基本已位于旧 ROI 内，左近角被机械臂遮挡；扩大范围用于给桌角、桌边物体上缘留出更多余量，不能恢复遮挡区域。

| 参数 | 原值 | 当前值 |
| --- | --- | --- |
| `inference_roi` | `[280, 330, 950, 670]` | `[220, 300, 1000, 700]` |
| `inference_tile_size` | 640 | 512 |

ROI 为原图像素 `[x0, y0, x1, y1]`，右端和下端不包含；新范围宽 780、高 400 像素。相较原值，左扩 60、上扩 30、右扩 50、下扩 30 像素。保留原有整幅 ROI 检测和重叠分块合并方法，检测掩码回填原图后再对应深度像素。

实际验证发现：仅扩大 ROI、保持旧 640 分块时，同一帧的碗会漏检；改为 512 分块后，原图中碗的完整掩码恢复。没有降低检测置信度和分块去重质量门槛。

- 同一帧旧配置检出 1 只碗，置信度 0.387，掩码 6500 像素；新配置检出 1 只，置信度 0.601，掩码 6509 像素。
- 修改后重新只读采集相机，检出 1 只碗，置信度 0.581，掩码 6679 像素，其中有效深度 6678 点。
- 48 项已有 ROI、分块和配置继承测试通过。源配置、覆盖配置和已安装配置读取结果一致。
- 以上验证只覆盖当前场景中的碗，未逐个桌角摆碗实测；不能据单帧结果承诺桌面每个位置的检测率。

配置文件：`src/yolo_vision/config/place_config.json` 和 `src/yolo_vision/config/live_table_20260928.json`。旧配置备份：`debug_output/table_roi_update_20260928/before/`。完整数据、修改前后对比与测试日志位于 `debug_output/table_roi_update_20260928/`。

原命令下一次启动即生效，无需重新开启准备脚本：

```bash
./run_pipeline_place_execute.sh --target-zone 左下
```

本次只读采集相机、回放检测及修改配置，没有机械臂或夹爪动作。桌子或相机位置改变后需要重新核对像素边界；被机械臂遮挡的位置需要调整观察姿态。
