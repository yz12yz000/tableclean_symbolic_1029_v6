# 夹爪稳定性复查（2026-09-28）

## 当前动作顺序

准备点确认打开 → 下降抓取 → 发送一次闭合并确认稳定 → 抬升搬运 → 下降到释放点 → 停留 1 秒 → 打开并确认 → 上退 → 返回起始点。

已打开时不重复发 Open，但需短暂稳定确认。闭合不要求历史上必须打开，也不要求相对于旧位置必须变化。搬运阶段没有 Open 指令；开合失败后停止后续动作，不自动释放或继续返程。

## 修复和等待参数

| 项目 | 当前值/处理 |
| --- | --- |
| 夹爪操作总超时 | 18 秒，进程启动和退出预留 2 秒 |
| 首次状态读取 | 最多 4 秒，计入总预算 |
| 已打开确认 | 至少 3 帧，稳定 0.4 秒，不发 Open |
| 开合后首次查询延时 | 0.2 秒 |
| 正常查询间隔 | 0.15 秒 |
| 漏包重查 | 每 0.5 秒，仅重发 GPP 查询 |
| 开合后稳定确认 | 3 秒，位置波动最多 1 原始计数 |
| 反馈断续 | 间隔超过 1 秒重新累计稳定时间 |
| 坏包恢复 | 错误长度、CRC 和截断帧逐字节重新同步 |

原先“已打开单帧即继续”可能在夹爪还在运动时提前下降，已改为短暂稳定确认。原解析器可能因损坏长度长时间等待、或把后续有效帧吞入坏帧而漏掉反馈，已补恢复逻辑及回归测试。以上是代码中发现的问题，不代表已证明过去每次超时的具体原因。

## 验证边界

开口和控制寄存器确认只能证明夹爪达到相应状态，不能证明碗被夹牢。当前没有搬运过程中夹紧力或掉碗检测。状态判定针对当前设备（张开位置 680±10 原始计数）；换夹爪、改变行程需重新校准。不要通过取消反馈检查掩盖持续通信故障。
