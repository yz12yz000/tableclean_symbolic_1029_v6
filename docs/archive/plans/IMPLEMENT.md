# 单碗五位置抓放与返回起点

## 项目目标

每次输入一个目标：左上、左下、中间、右上、右下。独立启动一次程序，获取当前新图像，要求恰好一只碗，定位抓取后送到该目标的示教准备点，沿基座 Z 负方向下降指定距离，停留、开爪、上退，再返回共同起始位置。返回后程序退出；下一次启动重新识别碗，不复用上一次候选，不在单次任务里循环测试多个位置。

现场已确认有人看护并能使用急停，逐点测试从上一位置重新抓取同一只碗。五次测试按五次独立启动执行。

## 实施步骤

1. 只读保存当前静止关节位置及 TF，作为固定起点。
2. 从五个原始采集 JSON 提取准备位姿，按静态 TF 转到程序工具帧，并保存每点下降距离。
3. 每次运行按目标读入配置快照，要求新观测恰好一只碗；原候选预检包含全部抓放及返回起点路径。
4. 抓取、抬升、搬运、下降、释放、上退、返回，最后确认关节与 TCP 到位，再报告成功并退出。
5. 构建三个 ROS 包，完成纯逻辑测试、隔离 ROS 和模拟 MoveIt 测试。
6. 实机先 plan-only，再逐个独立执行；每次检查碗实际落点、返回关节误差和新观测时间后再启动下一次。

## 约束条件

- 一个命令只处理一个目标、完成一次抓放；用户再次启动时重新定位。
- 五点下降距离不同，不得继续使用旧共用 0.20 m；不把负向位移误当绝对 Z。
- 返回使用保存的关节分支，不能用同一 TCP 的另一组 IK 解冒充起点。
- 保留原运动速度、候选回退、URDF 碰撞检查和停止逻辑。返程预检失败不开始抓取；运动中失败不强行返程或自动重抓。
- 当前仍无桌面碰撞模型及自动抓牢/落座传感反馈；实机结果必须结合现场监护和新图像判断。
- 单碗识别以当前桌面 ROI 为范围，移动桌子或相机后需要重新核对。放多只碗时会拒绝。

## 测试方法与验收标准

| 检查 | 验收标准 |
| --- | --- |
| 参数和位姿 | 五点独立映射、正确下降量、XY/姿态不变；错误/未启用点及缺失起点在运动前拒绝。 |
| 单次运行 | 完成计数为 1，返回后进程退出；下一次有新任务 UUID、新观测时间戳。 |
| 返回规划 | 抓取前生成七段完整规划；返程失败不提交计划；最终关节分支与保存值一致。 |
| 编译与离线回归 | `./run_pipeline_place_offline_test.sh` 构建成功，相关单测、隔离 ROS 和七段 MoveIt 模拟通过。 |
| 五点实机 | 五次独立启动，每次重新定位同一只碗，释放/上退/返程完成；记录实际碗位置、最终关节误差及执行日志。 |

./run_pipeline_place_execute.sh --target-zone 左上
